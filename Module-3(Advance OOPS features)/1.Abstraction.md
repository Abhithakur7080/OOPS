# Abstraction

Abstraction is one of the fundamental concepts of Object-Oriented Programming (OOP). It is the process of **hiding the implementation details** and showing only the necessary features or interface to the user. In simpler terms, abstraction allows us to focus on **what** an object does, rather than **how** it does it.

Abstraction is achieved through **abstract classes** and **interfaces** in languages like Java. It allows programmers to create a blueprint or template for objects without having to worry about their specific implementation details, making the system easier to use and manage.

---

## Key Features of Abstraction

- **Hiding Implementation Details:** The goal of abstraction is to hide the complex implementation details of a system and provide a simpler interface for interaction. For example, when you drive a car, you don't need to know how the engine works internally; you just need to know how to start the car, steer, and stop.
- **Abstract Methods:** These are methods declared in abstract classes or interfaces but have no body (i.e., they have no implementation). The implementation must be provided by the subclass or the class that implements the interface.
- **Concrete Methods:** These are methods with complete implementation in an abstract class. Subclasses inherit these methods, but they are also allowed to override them if necessary.

---

## Benefits of Abstraction in Programming

Abstraction allows programmers to:

| Benefit | Description |
|---|---|
| **Simplify the system** | By hiding unnecessary details, it reduces complexity. |
| **Improve maintainability** | Changes to implementation details don't affect the rest of the system. |
| **Increase reusability** | Code can be reused across different parts of the system with different implementations. |
| **Provide security** | Users interact with the system at a higher level, without modifying internal mechanisms. |

## Methods of Achieving Abstraction

In Java, abstraction can be implemented using:

1. Abstract Classes
2. Interfaces

## 1. Abstract Classes

An **abstract class** is a class that cannot be instantiated on its own and must be inherited by a subclass. It can have both:
- **Abstract methods** — declared but not implemented (subclass must implement)
- **Concrete methods** — fully implemented (subclass inherits or overrides)

```python
from typing import List
from abc import ABC, abstractmethod

# Abstract class
class Animal(ABC):
    def eat(self):
        print("This animal eats food.")

    @abstractmethod
    def sound(self):
        pass

# Concrete class Dog
class Dog(Animal):
    def sound(self):
        print("The dog barks.")

# Concrete class Cat
class Cat(Animal):
    def sound(self):
        print("The cat meows.")

# Main execution
if __name__ == "__main__":
    myDog = Dog()
    myCat = Cat()

    myDog.eat()    # Inherited concrete method
    myDog.sound()  # Overridden abstract method

    myCat.eat()    # Inherited concrete method
    myCat.sound()  # Overridden abstract method
```

**Output:**
```
This animal eats food.
The dog barks.
This animal eats food.
The cat meows.
```

**Explanation:**
- The `Animal` class is abstract and defines both an abstract method `sound()` (no body) and a concrete method `eat()` (has a body).
- The `Dog` and `Cat` classes are concrete classes that extend `Animal` and provide their own implementations for `sound()`.
- Objects of `Dog` and `Cat` can call both the inherited concrete `eat()` method and the overridden `sound()` method.

## 2. Interface

An **interface** is similar to an abstract class, but it can only contain abstract methods (until Java 8, after which default methods were introduced). All methods in an interface are implicitly abstract, and it is used to represent a **contract** that implementing classes must fulfill.

```python
from typing import List
from abc import ABC, abstractmethod

# Interface
class Animal(ABC):
    @abstractmethod
    def sound(self):
        pass

    @abstractmethod
    def eat(self):
        pass

# Dog class implementing Animal interface
class Dog(Animal):
    def sound(self):
        print("The dog barks.")

    def eat(self):
        print("The dog eats food.")

if __name__ == "__main__":
    myDog = Dog()
    myDog.eat()
    myDog.sound()
```

**Output:**
```
The dog eats food.
The dog barks.
```

**Explanation:**
- The `Animal` interface defines two abstract methods: `sound()` and `eat()`.
- The `Dog` class implements the `Animal` interface and provides concrete implementations for both methods.
- When we create an object of type `Dog`, we can call both `eat()` and `sound()`.

## Static and Default Methods

### 1. Static Method

Static methods belong to the **class** rather than any instance of the class. They can be called without creating an object and can only directly access static members.

```python
from typing import List

class Example:
    @staticmethod
    def staticMethod():
        print("This is a static method.")

if __name__ == "__main__":
    Example.staticMethod()  # Accessing static method directly using the class name
```

**Output:**
```
This is a static method.
```

**Key Points:**
- Called on the class itself, not on an instance.
- Used to perform operations common to all instances of a class.
- Can access only other static members (variables, methods) of the class.
- **Cannot** access instance variables or methods.

---

### 2. Default Method

Default methods were introduced in **Java 8** to allow adding new functionality to interfaces without breaking existing implementations. Prior to Java 8, interfaces could only declare method signatures.

```python
# NOTE: Python does NOT have default methods like Java interfaces.
# This example only demonstrates normal method inheritance from a base class.

from typing import List

class Example:
    def defaultMethod(self):
        print("This is a default method.")

class Demo(Example):
    pass  # Inherits defaultMethod

if __name__ == "__main__":
    obj = Demo()
    obj.defaultMethod()  # Accessing default method
```

**Output:**
```
This is a default method.
```

**Key Points:**
- Default methods have a body and are defined using the `default` keyword in the interface.
- They can be called on objects that implement the interface.
- They allow adding new methods to an interface without affecting existing implementing classes.
- A class that implements an interface with a default method can override it if needed.

#### Why Were Default Methods Introduced?

Before Java 8, adding a new method to an interface would **break all existing implementations** of that interface. To solve this, Java 8 introduced default methods, allowing interfaces to provide method implementations and ensuring existing classes can still work without modification.

**Use Cases:**
- **Backward compatibility:** Add new methods to interfaces without affecting existing classes.
- **Multiple interfaces:** Provide a default implementation to avoid conflicts when a class implements multiple interfaces with the same method signature.

## Important Questions

### Q: Can an abstract class extend another abstract class?

**Ans:** Yes, an abstract class can extend another abstract class in Java.

The subclass (child abstract class) will inherit the abstract methods and behaviors of the parent class, but it is **not required** to implement the abstract methods unless it is a concrete class.

If the subclass is also abstract, it can either:
- Implement the abstract methods from the parent class, or
- Leave them unimplemented (in which case, the subclass must also be declared `abstract`).

---

### Q: Can an abstract class have a constructor and can we create an instance of it?

**Ans:** **No**, you cannot create an instance of an abstract class directly in Java. An abstract class is designed to be inherited, not instantiated on its own.

However, an abstract class **can have a constructor**, which is invoked by a subclass when an instance of the subclass is created. This allows the abstract class to initialize its fields before the subclass adds its own behavior.

**Key Points:**

| Point | Detail |
|---|---|
| **Abstract Class Constructor** | Can have constructors, but cannot instantiate the abstract class directly. |
| **Subclass Constructor** | Can call the abstract class constructor using the `super()` keyword. |
