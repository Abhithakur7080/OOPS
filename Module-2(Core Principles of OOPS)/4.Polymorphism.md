# Polymorphism

Polymorphism is one of the key concepts in object-oriented programming (OOP) and refers to the ability of a single entity (like a method, operator, or object) to **behave differently in different contexts**. The term "polymorphism" is derived from Greek, meaning **"many forms."**

In programming, it allows the same method or object to perform different tasks depending on the context.

---

## Types of Polymorphism

There are two main types of polymorphism in Java:

1. **Compile-Time Polymorphism** (Static Polymorphism)
2. **Run-Time Polymorphism** (Dynamic Polymorphism)

---

## 1. Compile-Time Polymorphism (Static Polymorphism)

In **compile-time polymorphism**, the method to be called is **resolved at compile time**. When we say the method is "resolved" at compile-time, it means that the compiler determines the correct method to invoke based on the method's **signature** (method name, parameters, etc.).

It is achieved through:
- **Method Overloading**
- Operator Overloading *(not supported in Java)*

```python
from typing import List

class Calculator:
    def add(self, a, b):
        return a + b  # Works for both int and float due to Python's dynamic typing

if __name__ == "__main__":
    calc = Calculator()

    print(calc.add(5, 3))       # Calls with integers   → Output: 8
    print(calc.add(5.5, 3.3))   # Calls with floats     → Output: 8.8
```

In this case, the compiler determines whether to call `add(int, int)` or `add(double, double)` at **compile-time** based on the types of arguments passed.

**Output:**
```
8
8.8
```

### Key Points

| Point | Detail |
|-------|--------|
| **Resolution** | Determined at **compile-time** |
| **Speed** | Faster execution since binding is done early |
| **Examples** | Method Overloading |

> **Note:** The return type **cannot** be a differentiator for Method Overloading.

---

## 2. Run-Time Polymorphism (Dynamic Polymorphism)

In **run-time polymorphism**, the method is resolved **during runtime**. It is achieved through **method overriding**.

When we say the method is "resolved" at run-time, the decision about which method to call is made **while the program is actually running**. This occurs due to the **dynamic method dispatch** mechanism, where the JVM decides which method of a subclass to call based on the **actual object type** (not the reference type) at runtime.

```python
from typing import List

# Parent class
class Animal:
    def sound(self):
        print("Animal makes a sound")

# Child class
class Dog(Animal):
    def sound(self):
        print("Dog barks")

# Main
if __name__ == "__main__":
    myAnimal = Dog()   # Animal reference not needed, Python is dynamic
    myAnimal.sound()   # Calls Dog's sound() method at runtime
```

Here, the method to be executed is decided at **runtime** based on the object type.

**Output:**
```
Dog barks
```

### Key Points

| Point | Detail |
|-------|--------|
| **Resolution** | Determined at **runtime** |
| **Speed** | Slower compared to compile-time polymorphism due to late binding |
| **Examples** | Method Overriding |

---

## Comparison: Compile-Time vs Run-Time Polymorphism

| Feature | Compile-Time Polymorphism | Run-Time Polymorphism |
|---|---|---|
| **Also known as** | Static Polymorphism | Dynamic Polymorphism |
| **Resolved at** | Compile time | Runtime |
| **Achieved by** | Method Overloading | Method Overriding |
| **Binding** | Early Binding | Late Binding |
| **Execution Speed** | Faster | Slower |
| **Inheritance required** | No | Yes |
| **Flexibility** | Less flexible | More flexible |

---

## Quick Summary

```
Polymorphism
│
├── Compile-Time (Static)
│   └── Method Overloading
│       → Same method name, different parameters
│       → Resolved by the compiler
│
└── Run-Time (Dynamic)
    └── Method Overriding
        → Same method name & signature in parent + child
        → Resolved by the JVM at runtime
```
