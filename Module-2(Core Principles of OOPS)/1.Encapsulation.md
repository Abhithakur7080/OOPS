# Encapsulation in Python (Data Hiding)

## Introduction

Encapsulation is a fundamental concept in **Object-Oriented Programming (OOP)** where the internal details (data and logic) of an object are hidden from the outside world.

It is the process of **bundling data (attributes) and methods (functions)** into a single unit (class) and restricting direct access to some of the object's components.

👉 Goal: Protect data and allow controlled access.

---

## Key Concept

Encapsulation ensures:

* Data is **hidden (private)**
* Access is provided via **methods (getter/setter)**
* Internal state cannot be modified directly

### Types of Access (Python Convention)

| Type      | Syntax   | Description                                     |
| --------- | -------- | ----------------------------------------------- |
| Public    | `name`   | Accessible everywhere                           |
| Protected | `_name`  | Should not be accessed directly (by convention) |
| Private   | `__name` | Name mangling applied                           |

---

## Why Encapsulation is Important

### 1. Data Security

* Protects sensitive data
* Prevents unauthorized modification

### 2. Flexibility & Maintenance

* Internal implementation can change
* External code remains unaffected

### 3. Modular Code

* Combines data and behavior
* Improves readability and structure

### 4. Easier Debugging & Testing

* Controlled access simplifies testing
* Errors are easier to track

### 5. Reduced Complexity

* Hides internal logic
* Makes usage simple

---

## Example: Bank Account System

```python
class BankAccount:

    def __init__(self, accountHolderName, balance):
        self.__accountHolderName = accountHolderName
        self.__balance = balance

    def getAccountHolderName(self):
        return self.__accountHolderName

    def setAccountHolderName(self, name):
        self.__accountHolderName = name

    def getBalance(self):
        return self.__balance

    def deposit(self, amount):
        if amount > 0:
            self.__balance += amount
        else:
            print("Deposit must be positive")

    def withdraw(self, amount):
        if amount > self.__balance:
            print("Insufficient funds")
        else:
            self.__balance -= amount


# Usage
account = BankAccount("John Doe", 5000)

print(account.getAccountHolderName())
print(account.getBalance())

account.deposit(1500)
account.withdraw(2000)

print(account.getBalance())
```

## Explanation of Example

### 🔒 Private Attributes

```python
self.__balance
self.__accountHolderName
```

* Python uses **name mangling**

### 🔓 Getter Methods

```python
def getBalance(self):
    return self.__balance
```

* Used to **read data safely**

### ✏️ Setter / Modifier Methods

```python
def deposit(self, amount):
```

* Adds validation
* Prevents invalid data

## Key Takeaways

* Encapsulation = **Data Hiding + Controlled Access**
* Private variables use `__`
* Access via methods only
* Helps maintain **data integrity**
* Improves **code quality & security**

---

## Important Note

Encapsulation is a **design principle**, not a strict rule in Python.

* Python does not enforce strict access control
* It follows **naming conventions**
* Developers are expected to respect it
